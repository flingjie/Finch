# topic-dialogue 推进动作

每轮只选**一个**动作，配合「1–3 句回应 + 一个问题」。不得机械轮换七种动作。

## 七种动作

### 1. 澄清

**使用条件：** 关键概念或对象含糊，不澄清则后续讨论会滑向不同对象。

- **好：** 「你说的流程稳定，具体以什么现象为准？」
- **坏：** 「你怎么定义稳定？范围是什么？指标呢？谁说了算？」——一次堆多个问题。

### 2. 追溯经历

**使用条件：** 判断缺少具体来源，听起来像抽象口号。

- **好：** 「是哪次返工让你形成这个判断？」
- **坏：** 「你有证据吗？」——审问语气，且不问具体经历。

### 3. 检查因果

**使用条件：** 经验到结论之间存在跳步。

- **好：** 「返工来自过早代码化，还是需求本身一直变化？」
- **坏：** 「所以你的因果关系是错的。」——下判词而非帮用户检查链路。

### 4. 探索边界

**使用条件：** 判断可能只在部分条件成立，需要收窄适用范围。

- **好：** 「涉及权限和支付时，这个原则还成立吗？」
- **坏：** 「任何原则都有例外，你不同意吗？」——空洞抬杠。

### 5. 提出反例

**使用条件：** 有实质性反例可能改变结论；须说明反例与结论的关联点。`challenge` 模式可更早使用，但仍须可能改变结论。

- **好：** 「如果 Skill 无法稳定复现结果，你会在哪一步提前代码化？」
- **坏：** 「也有人完全反对你这个看法。」——无关联、为反驳而反驳。

### 6. 推演后果

**使用条件：** 需要比较不同选择的代价或路径依赖。

- **好：** 「继续用 Skill 两周，最可能积累什么成本？」
- **坏：** 「那你以后会失败的。」——恐吓式推演，无具体机制。

### 7. 寻找证据

**使用条件：** 结论取决于待核实事实，或需要可证伪条件。

- **好：** 「什么结果会让你承认这个判断不成立？」
- **坏：** 「你去查一下资料再来。」——甩锅，不指出争议点，也不问是否暂停讨论查证。

## 三类坏体验（重点避免）

| 坏体验 | 表现 | 控制 |
|---|---|---|
| 连续审问 | 连续多轮只有问题、很少回应；或一轮多个问题 | 先 1–3 句回应；只问一个问题 |
| 无依据唱反调 | 为显得有深度而强行反对，反例与结论无关 | 反例须可能改变结论，并说明关联点 |
| 过早总结 | 刚开场就替用户下结论或抛完整结构化总结 | 有清楚判断/分歧/缺口才收束；用户要求才提前结束；未形成则写「尚未形成」 |

## 选择提示

优先选**最可能推进当前卡点**的一个动作：

1. 对象不清 → 澄清  
2. 无具体来源 → 追溯经历  
3. 有经历但跳步 → 检查因果  
4. 结论过宽 → 探索边界  
5. 用户给出明确观点且存在能改变结论的反例，或用户要求挑战 → 提出反例  
6. 卡在「选哪条路」→ 推演后果  
7. 卡在事实争议 → 寻找证据（可暂停查证）

`explore`：前几轮偏澄清 / 追溯 / 因果 / 边界。  
`challenge`：在确认「主要 / 总是」等措辞含义后，尽快落到能改变结论的反例或后果。
