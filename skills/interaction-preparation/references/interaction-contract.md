# 互动贡献契约

`Artifact` 是**可审阅成果**，不是已发生的互动。机会经 `connect prepare` 生成正文后走到
`ready`，正文与来源一起返回。

- 形式由机会的 `proposal.form` 决定：`reply_draft` / `method_card` / `clarifying_question` /
  `case` / `demo`（`clarifying_question` 落成 `reply_draft`）。
- `source_refs` 来自机会的 `evidence_refs`，是正文的事实来源；正文只允许提问或明确标注推测。
- `execution_status` 只描述是否运行：`not_run` 表示未运行，不得标为 `ran_ok`。

## 理解经历与试用意图（不新建销售枚举）

一条建议聚焦**一个**自然的下一步，不一次追问完整商业问卷。没有自己的相关经验时，
不编造「我也遇到过」。生成正文不是发送；`ready` 也不是已发生互动。

| 意图 | 优先内容 |
|---|---|
| 了解问题 | 最近一次发生在什么任务中？现在怎样处理？有何约束？ |
| 提供帮助 | 给出相关案例、样例或经验，并说明适用限制 |
| 请求样本 | 说明用途，只请求必要材料，允许对方拒绝 |
| 邀请试用 | 仅在已有相关工具且情境匹配时；说明能做什么和已知限制；先给有用信息 |

第一次互动优先给对方有用的信息或提出具体问题，**不要**开场推销。

## 正文约束

- 互动轨道不携带作者个人证据：正文只允许提问或明确标注推测，禁止虚构案例/代码/实验。
- 外部帖子只是信号，不是个人证据；不把别人的经历写成用户经历。
- `ready` 只表示成果可审阅，不等于已发布；真正发送后经 `finch connections record` 登记。

## 三事实分离

`Opportunity`（交流机会 + 生命周期）、`Artifact`（可审阅成果）、`InteractionRecord`
（已发生互动）是三个不同事实，不得互相替代。
