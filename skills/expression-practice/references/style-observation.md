# 风格观察

从多次练习中积累候选观察，用户确认后才进入 voice-profile。

## 触发条件

- 至少 **3 个独立练习**出现相似选择（同一练习维度 + 同一写法，或同一方法），才提出候选观察。
- 这是产品默认值，不是统计证明。

## 观察内容

每条观察包含：

- **特点**：一句话概括反复出现的选择。
- **证据**：对应会话与**用户原句**（可追溯的用户创作片段）。
- **适用场景**：该特点在什么情境下成立。
- **反例 / 不确定性**：何时不成立，或证据是否可能来自当次练习要求。
- **确认状态**：待确认（pending）/ 认可（accepted）/ 修正（corrected）/ 否定（rejected）。

## 确认与边界

- 观察**不自动写入** VoiceProfile；用户认可后走现有 `finch voice` 流程（`approve-example`）。
- 用户否定的观察**保留反馈**，避免反复提出同一判断。
- AI 示例与用户作品分开记录：`final_source=ai_example` 的会话（只看过/采用 AI 稿）**不进入**
  风格观察，不产生用户创作证据；混合文本（`final_source=mixed`）风格证据优先引用用户
  明确修改的片段（`user_actions[]` 中 `edit` 的 `text`），无法确定片段来源时不采集。
- 表达偏好（用户多次喜欢某类结构、删掉某类措辞）单独命名记录，不证明用户会独立写出，
  不与 voice-profile 创作例句混合。
- 新画像只影响推荐，**不锁死写法**：继续保留一种相邻变化与一种陌生尝试。

## CLI

- `finch practice observe`：提出候选（≥3 次相似练习，幂等）。
- `finch practice observe --list`：列出已有观察。
- `finch practice observe --accept <id>` / `--reject <id>` / `--correct <id> --note "..."`：确认状态。
