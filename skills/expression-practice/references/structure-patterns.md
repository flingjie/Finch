# 结构骨架

草稿后附一份**思路骨架**（`structure_hint`），说明作者准备说什么、用什么支持、怎样安排段落。
它不是模型内部推理过程，也不宣称揭示模型如何得到答案；它是可核查的**内容组织说明**。

骨架作为草稿版本的附属对象保存（见 `session-output.md`），每步必须带**当次素材的具体内容**，
不能只有「主张 / 理由 / 例子」空标签。默认只展示与这篇内容直接相关的骨架，不做七维评分、长篇
诊断或必答问卷。

## 四种种子结构

这些是推荐起点，不是强制正文模板；允许删、合、调整步骤。每次给一种，用户要求比较时再给替代
结构。短推文可以在一句中承载多个步骤，不强制拆成四段；故事、幽默或情绪表达可采用更轻的结构，
不为了补齐标签改变作者意思。

| 素材 | 结构（pattern_id） | 重点 | 不适用情况 |
| --- | --- | --- | --- |
| 经历、复盘 | 预期 → 实际发生 → 判断变化 → 下一步（`review`） | 从事件提炼认识，区分事实与解释 | 没有真实经历时不能伪造现场；可改写为假设讨论 |
| 观点、评论 | 主张 → 理由 → 例子 → 适用边界（`opinion`） | 让判断有依据并保留条件 | 单纯情绪表达不必补齐整套论证 |
| 问题、方案 | 问题 → 原因假设 → 方案 → 验证（`solution`） | 避免从问题直接跳到解决方案 | 根因已经证实时应标明证据，不继续伪称假设 |
| 概念解释 | 读者疑问 → 具体例子 → 核心机制 → 使用条件（`explanation`） | 让读者从熟悉场景进入抽象概念 | 类比会误导机制时不用；无需编造例子 |

匹配不上任何结构时用 `custom`，并用自己的步骤顺序说明，不强行套四段。

## 每步（step）的字段

- `role`：短标签（observation / expectation / claim / reason / example / boundary / action /
  verification / …），自由但需有区分度。
- `label`：展示名（如「实际发生」「判断变化」）。
- `content`：**当次素材里的具体内容**，不可为空标签。
- `basis`：内容来源 —— `user_material`（用户提供）/ `sourced`（已引用来源）/ `proposed`（AI
  建议的主张或结构安排，不能当成用户已认可的立场）/ `unknown`。这是来源标记，不是事实真伪认证；
  用户提供的说法仍可能待验证。
- `source_refs`：只使用实际提供或检索到的引用，不生成虚假来源。
- `draft_excerpt`：该步对应的正文原句摘录，可空；存在时必须匹配对应版本原文。

## 选择规则

- 优先复用 `methods` 中适合的结构方法；四种种子结构是轻量兜底，不为每次请求扫描所有方法或
  默认启动外部搜索。
- 一个缺口的骨架解释（`rationale`）只解释**一次具体选择及其代价**，不输出通用写作课。
- 用户确认结构只记偏好或认可，不把 AI 骨架自动转成用户创作；用户自行补充的理由单独保存原话
  与来源。

## 反例

- 把「预期 → 实际 → 判断 → 下一步」套在没有真实经历的推演话题上，并把推演写成已发生的经历。
- 步骤内容只写「主张、理由、例子」而不填任何当次素材细节。
- 短推文硬拆成四段、为凑结构标签补造细节。
- 在 `source_refs` 里写不存在的出处。

## 精简展示示例（example 模式）

> 【思路骨架】预期：评估过关，可以上线 → 反差：推演发现多步执行可能超时 → 判断：答案评分
> 不足以覆盖执行风险 → 行动：准备通过影子模式观察真实请求。
>
> 【关键选择】先展示反差，再提出行动。
>
> 【思考缺口】影子模式提供观察机会，不能仅凭启用它就断言风险已解决。

正文、骨架、缺口与可选小动作的展示顺序见 `SKILL.md`。
