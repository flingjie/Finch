# 练习动作示例与不适用情形

predict / hint / transfer 是 **independent 模式**的**可选**微工具，不再是唯一训练路径。independent
主路径是「三种写法 → 用户写 → 局部对比 → 用户重写」（见 `option-selection.md` /
`diagnosis-rules.md`）。example 模式用「一个可选小动作」、guided 模式用「一个续写任务」替代
这些微工具（见 SKILL.md 三种模式）。三个可选动作只给少量例子与「何时不该用」，不堆大而全的方法目录。

## 预测（predict）

任务形式：「读者看完这段，会认为你在建议什么？」

- 例：作者想表达「按审查能力安排生成量」，但文本读起来像「建议限制 AI 写代码」。
  反馈给一种有文本依据的误读，让作者自己修订。
- 不适用：正文还没说清自己的判断（先走 revise）；或读者会读到什么毫无歧义、没有可预测的误读。

## 提示（hint）

仅在用户卡住或明确求助时启用，逐级给最小帮助：

1. 问题提示：「把『效率提高』换成谁少做了哪一步。」
2. 局部骨架：「原来需要___，现在___，但新增了___。」
3. 局部参考：只示范一两句，标注为 AI 参考，不当作用户修订。

- 不适用：用户没求助就不给；不因回答慢或时间经过自动升级；用户要求完整代写 → 若只是要成稿走
  `finch drafts`，若愿意看例子学写法切 `example` 模式（`finch practice mode <id> --set example`）。

## 迁移（transfer）

正文已讲清楚后，改**一个**条件重新表达：

- 例：面向非技术产品经理，用两句话表达同一判断，保留关键条件。
- 例：把「审查瓶颈」的例子从工程师换成数据分析师，重写核心句。
- 不适用：正文本身还没讲清楚（先 revise）；一次改多个条件（受众+篇幅+例子一起改会掩盖问题）；
  迁移与当前练习目标无关时不硬凑。

## 收尾时的迁移观察

只有完成了迁移练习，收尾才可说明「本次迁移观察」；没做就写「迁移尚未检验」，
不把迁移答案当作终稿，也不宣称能力已长期提升。
