# 写法选择规则

`finch practice explore` 给三种写法方案（**仅 independent 模式**），本文件约束三方案的实质差异、
熟悉程度判定与推荐来源。example / guided 模式直接走 `finch practice draft`，不经三方案。

## 三种方案

- **熟悉**：用户历史上常用或明显偏好的写法。
- **相邻变化**：与熟悉写法共享一部分，但改一个主要维度。
- **陌生尝试**：用户少用但**适合当次素材**的写法。

三种方案必须存在**可解释的差异**，不能换标题后重复相同结构；单次优先改变一个主要维度。

## 熟悉程度判定

- 以用户练习历史 / voice-profile 为依据；**没有历史时明确写「暂定」**，不虚构偏好。
- 只有真实历史才能标「熟悉」；新用户或新素材不得声称「你习惯这样写」。

## 推荐来源与方法库

- 优先复用已分析文章中用户选中的方法（`finch methods list` / `show`）。
- 种子写法库（`finch methods seed`，EP-CW-001..048）按类型接入：
  - **写作技巧**（method_type=technique）→ 用于三方案推荐或局部反馈。
  - **训练方法**（method_type=training）→ 用户卡住时选**一个**训练任务。
  - **场景原则**（method_type=scenario）→ 仅在相应场景激活，不硬塞。
  - 「待补充」条目（`executable=false`）不进入可执行推荐。
- 不凭作者名字杜撰其风格；不默认每次练习都外部搜索。

## 展示边界

- 每种方案只展示：写法名称与熟悉程度 / 切入点 / 两至三步推进路径 / 阅读效果与代价 /
  需要用户补充的事实 / 本次主要练习维度。
- **independent 模式**不给完整开头、全文或逐句提纲；不把练习设计成补齐 AI 已写好的段落。
  example 模式允许一版完整草稿，guided 模式允许局部开头/框架（见 SKILL.md 三种模式）。
