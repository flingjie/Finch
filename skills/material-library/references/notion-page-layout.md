# Notion 页面布局（user region vs Finch region）

素材页正文由三段组成，用 `heading_2` / `heading_3` 标记分隔。标记文本是 canonical，不改变：

```
# heading_2  原始记录
  用户的事件描述、原话、摘录、图片与附件（可空，仅标题也有效）
# heading_2  我的感触          ← 可选，用户亲自提供
  用户自己的感触
# heading_3  Finch 讨论记录 #<discussion_id>   ← 每个讨论一块，追加到页尾
  判断：<用户判断>
  AI 提议：<提议>
  未解决：<问题>
  行动：<下一步>
```

规则：

- **只追加不重写**：Finch 讨论块永远追加到页尾；用户原文、用户改过的讨论块不覆盖、不恢复。
- **块 id / 操作 id 管理**：Finch 区靠讨论块的 `heading_3` 标记（`Finch 讨论记录 #<discussion_id>`）
  与操作 id 管理，不靠标题文本辨认。
- **部分写入恢复**：写回前全量读块、扫标记——无标记→整段追加；有标记但尾部缺失→只补缺失尾块；
  齐全→幂等不重复；标记在但内容对不上（用户已编辑）→不覆盖、不重复追加。
- **无固定格式**：用户可自由写正文，不要求遵循固定格式才能导入；模板只是提示。无法可靠识别
  「我的感触」时保持为空，不用模型猜测填充。

## 属性

| 属性 | 类型 | 维护方 |
|---|---|---|
| 标题 | title | 用户为主；Finch 创建时可写入，不自动重命名 |
| 来源链接 | url | 用户维护；Finch 记录时可按输入填入 |
| 主题标签 | multi_select | Finch 提议；用户修改后不覆盖 |
| 已讨论 | checkbox | 有实际保存的讨论后由 Finch 更新 |
| 创建/修改时间 | 系统只读 | 远端提供 |
| Finch 操作标识 | rich_text | 系统维护（create 去重键），不要求用户填写 |
