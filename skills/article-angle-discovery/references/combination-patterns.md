# 组合模式（把「独特角度」变成组合过程）

「独特角度」不是凭空发明，而是一个组合过程：从原文取一个观点，与另一份有依据的材料连接，
产生读者用得上的新判断。只盯着原文找角度，很容易停在解释、赞同或反对。

先问：**这篇文章的哪个观点，能帮助我重新理解一个真实问题？**

## 第二份材料从哪来

第二份材料不限于实践记录，可来自任何有出处的地方：实践记录 / 失败记录 / 其它文章 / 已有方法 /
领域通识 / 读者自身的问题。每条材料必须带来源；来源用于诚实标注，不冒充亲历。

## 组合方式

不必每次用完所有方式，选最有材料支撑的两三种即可。

| 组合方式 | 要寻找的连接 | 可能带来的增量 |
|---|---|---|
| 原文观点＋个人实践 | 观点在实际操作中如何成立 | 可执行步骤、真实限制 |
| 两篇文章的观点 | 两者互补或冲突在哪里 | 新解释、适用条件 |
| 原文方法＋另一领域 | 是否存在相似的问题结构 | 可验证的迁移方案 |
| 原文建议＋失败案例 | 什么条件下建议失效 | 边界、修正方法 |
| 原文主张＋现实约束 | 时间、成本、权限如何影响选择 | 更具体的取舍 |

## 为什么能连起来（桥）

「Agent＋心理学」「写作＋工程」只是主题并列，不构成有效组合。有效组合需要一座桥：

- 它们共同解决什么问题？
- 第二份材料补上了原文的哪个缺口？
- 两者有什么关键差异？
- 组合后，读者会改变什么判断或行动？

## 试金石

> **拿掉第二份材料，结论是否基本不变？**

如果不变，它可能只是装饰性类比，应该合并或淘汰。

## 工作示例（方案，非已验证）

原文主张：「AI 演示太顺滑，容易让人产生已经学会的错觉。」

第二份材料：「软件测试可以改变输入，检查系统行为。」（来源：已有方法 / 领域通识）

组合后提出一个待验证的角度：

> 学习 Agent 工作流时，能否用故障注入检查自己是否真的理解？

具体做法：先预测工具超时、重复返回或缺少字段时会发生什么，再运行工作流，对照结果。

这个组合增加了三样东西：测试条件、理解程度的观察方式、可重复的练习。它贴合「把概念变成可用工具」的
方向，但在实际试验前，应保留为方案，不能写成「我已验证有效」。
