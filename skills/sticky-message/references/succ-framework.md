# SUCCESs Framework

From Made to Stick (Chip & Dan Heath). Six dimensions that make an idea stick.
You are NOT required to hit all six — diagnose which dimensions the message is
missing, then fix those. A strong message usually has a clear core + at least one
gap + one concrete example + one reason to care.

## Simple

The core that survives compression. If the audience remembers only one thing,
what should it be?

Questions:
- What is the single most important idea?
- What can be removed without destroying the idea?
- What belief should change after hearing it?

Bad:
> We provide an AI agent platform with multi-agent orchestration, workflow
> execution, and context management.

Good:
> Make AI agents work like a reliable team instead of a clever chatbot.

## Unexpected

A gap between what the audience expects and what is true. Surprise opens a hole;
the core fills it. Surprise without relevance is noise — the gap must lead
straight back to the core.

Questions:
- What does the audience currently believe?
- What seems obvious to them?
- What assumption needs to be challenged?

## Concrete

Replace abstractions with observable reality: real people, tasks, objects,
actions, failures, and consequences.

Questions:
- Can someone visualize this?
- If not, what would they need to see or do to believe it?

Bad:
> Agents need better reliability mechanisms.

Good:
> The agent fixed the code, deployed it, and production was still broken.

## Credible

How can the audience verify it for themselves? Prefer bottom-up over top-down:

demonstration → testable claim → personal experience → anti-authority detail
→ data → authority.

Prefer "Don't believe me — try this and see what happens" over "Trust me."

## Emotional

Why should they care? Translate feature → consequence, capability → outcome,
technology → user problem.

Questions:
- What gets easier?
- What risk disappears?
- What pain is removed?
- What opportunity becomes possible?

## Story

The narrative already inside the idea — not an invented plot:

Character → Goal → Obstacle → Failure / Conflict → Discovery → Resolution.

The story should demonstrate the principle, not merely decorate it.

## Quality Check

Before finalizing, evaluate:

| Dimension | Question |
|---|---|
| Simple | Can the core survive compression? |
| Unexpected | Does it challenge an assumption? |
| Concrete | Can people visualize it? |
| Credible | Why should they believe it? |
| Emotional | Why should they care? |
| Story | Can it be demonstrated through events? |

Do not force every dimension. Mark a dimension "not needed" rather than filling
it with a weak version.
